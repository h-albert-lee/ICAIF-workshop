\section{Experimental Setup}
\label{sec:setup}

\paragraph{Systems and data use.}
The core comparison comprises Qwen3.5-2B, Qwen3.5-4B and Kanana-2-3B-Instruct, plus Presidio with Korean/custom rules, ko-pii and OpenMed's multilingual privacy filter. An exploratory extension adds Qwen3.5-9B and Kanana-1.5-8B-Instruct-2505 after initial reports of small-model formatting failures; it does not replace the core runs. The Kanana comparison also changes model generation. No system is trained on the benchmark. Prompt, label-map and decoding choices are frozen on separate, non-overlapping pilot examples. Exact revisions, serving precision and inference settings accompany each completed run.

\paragraph{Matched context conditions.}
We vary available context while holding the extraction target fixed. A gold-blind character partition assigns each span start to one target core. In \emph{full-context, targeted-output} extraction, each request receives the entire document and returns only spans starting in its core. A following halo permits completion of crossing spans. The \emph{local-window} condition uses the same core and output halo but restricts the surrounding input to nearby text. Exact quotations and occurrence indices are converted to Unicode offsets and merged by document, without fuzzy repair. Provisional settings are 1,200-character cores, 1,200-character halos and a 4,096-token output cap; the final pilot-frozen values must be reported. Gold spans that the output protocol cannot represent remain in the denominator and are identified by a coverage audit.

\paragraph{Capacity and failure accounting.}
Native tokenizer counts with chat framing and output reserves determine common eligible documents across models and both conditions before inference. We report exclusions and never silently truncate inputs. Invalid JSON, invalid items, truncated outputs and failed requests yield empty predictions for the affected core, retaining its gold false negatives; no automatic retries are used. The protocol requires retaining full received responses for audits and disclosing logging gaps. Failure analysis distinguishes model formatting, output truncation and transport/adapter errors. Thus headline F1 evaluates the complete extraction system, including output reliability. Request counts, tokens, cost and latency account for repeated full-document inputs. Paired document bootstrap (2,000 resamples, seed 0) estimates uncertainty in the full/local difference. Extension results remain separate until common-cohort and execution provenance are reconciled.
